# Finance Panel

Кабінет транзакцій на React + Vite + TypeScript (strict).

## Запуск

1. `npm install`
2. Створи `.env.local` за `.env.example`. Під час міграції існуючі ключі вже перенесено без змін.
3. `npm run dev`

Перевірки: `npm run build`, `npm run lint`, `npm test`, `npm run test:e2e`, `npm run format:check`.
Браузерні тести використовують встановлений Microsoft Edge. Для іншого середовища зміни channel у playwright.config.ts та встанови відповідний браузер Playwright.

## Архітектура

- `src/app` — провайдери, React Router (Data Mode), QueryClient, layout.
- `src/pages` — екрани, які підключають модулі; завантажуються за потребою.
- `src/features/transactions` — типи, Zod-перевірка двох джерел, нормалізація, розрахунки і запити.
- `src/features/exchange-rates` — перевірка курсів, кеш і список популярних валют.
- `src/shared` — HTTP-клієнт, десяткова арифметика, форматування і спільні UI-компоненти.
- `src/test`, `*.test.ts(x)`, `e2e` — налаштування та перевірки.

Ant Design використовується для UI, таблиць і форм; CSS Modules — для layout. Серверні дані належать TanStack Query. Локальні значення — React/Form, пошук, статус і сторінка таблиці — URL. Окремий глобальний store не потрібний.

Маршрути: `/dashboard`, `/transactions`, `/transactions/:id`, `/exchange-rates`, `/converter`.

## Дані та розрахунки

Джерела finance1 і finance2 завантажуються паралельно з заголовком x-api-key. finance1 містить об’єкти, finance2 — рядки. Зберігаємо всі транзакції для показу, але у сумах враховуємо лише paid або без статусу. Коди валют нормалізуються до великих літер.

Загальна сума завжди в USD. Окремі суми USD/EUR показують початкові враховані транзакції до конвертації. Для переведення в USD ділимо на курс вихідної валюти. Курси CurrencyFreaks — поточні, відносно USD, з датою сервісу.

Суми і курси зберігаємо як строки. decimal.js використовує 40 значущих цифр та ROUND_HALF_UP, округлюємо підсумок до двох знаків. Числа, що прийшли як JSON number, вже можуть втратити точність на стороні API: для виробничого контракту потрібні десяткові строки або мінімальні одиниці.

Офіційні фінансові підсумки, історичні курси й бухгалтерські операції мають визначатися backend. Калькулятор показує попередній еквівалент.

Транзакції кешуються на 1 хвилину, курси — на 15 хвилин. Кнопки оновлення примусово перезапитують дані. При невдалій фоновій перевірці кешовані дані можуть залишатися видимими разом із повідомленням про помилку. Одна помилка курсів не приховує транзакції та початкові суми. Логи не містять ключів або сирих мережевих помилок.

## Обмеження поточного API

API не надає справжніх ID, дат транзакцій, авторизації бізнесів, редагування або серверної пагінації. ID для детальної сторінки поки утворюється з джерела та індексу; він не є стабільним при зміні порядку відповіді. Пошук, сортування й пагінація працюють по повністю завантаженому набору. Для великого обсягу слід підключити серверні параметри й агрегати.

Після появи авторизації додай бізнес-ID до query keys, очищення кеша при виході та серверні перевірки прав. Зараз застосунок не реалізує вхід чи управління операціями.

Змінні VITE_* доступні браузеру. Поточне пряме підключення збережене з попереднього проєкту; перед публічним розгортанням ключі зовнішніх сервісів потрібно перенести на backend. Для BrowserRouter налаштуй SPA fallback на index.html.
